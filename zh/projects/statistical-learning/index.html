統計學習：文字分類與價格預測

以 Python 完成兩項機器學習實作，分別針對職缺與人才匹配進行分類預測，以及根據商品名稱建立價格預測模型。透過文字特徵工程、模型訓練、超參數調整與交叉驗證，比較不同演算法的預測表現，並在模型效能與運算成本之間做出技術取捨。

01

專案概述

這兩項研究聚焦於如何將非結構化文字轉換為可供機器學習模型使用的特徵，並依據不同預測任務選擇適合的演算法與評估方式。

第一項專案為職缺與人才匹配分類，結合職缺描述、求職者技能及結構化資料，預測人才與職缺的匹配結果，並探討特徵工程、類別不平衡與分類門檻對 F1 Score 的影響。

第二項專案為商品名稱價格預測，從商品名稱提取文字與數值特徵，建立價格迴歸模型，並在運算時間與記憶體限制下，比較模型誤差與實作效率。

兩項實作涵蓋從資料前處理、特徵設計、模型訓練到驗證分析的機器學習流程，也讓我實際理解資料品質、特徵表示與模型選擇如何共同影響預測結果。

02

職缺與人才匹配分類

此專案的目標是根據職缺與求職者資料建立分類模型，判斷人才是否符合職缺需求。由於資料包含大量中文文字、類別欄位及數值資訊，我首先進行資料清理與特徵工程，將不同類型的資料轉換為模型可使用的輸入特徵。

在文字處理方面，我使用TF-IDF Vectorization提取職缺描述與人才資料中的文字特徵，搭配單詞與雙詞 n-gram，保留部分詞語組合資訊。同時使用 One-Hot Encoding 處理類別變數，並透過缺值填補與數值區間轉換，整理結構化資料。

除了基本文字特徵，我也實作技能匹配與自訂特徵，例如比較求職者技能與職缺要求，以及整理年齡、薪資等相關欄位，讓模型能使用更貼近實際匹配問題的資訊。

模型部分，我以Logistic Regression 作為基準模型，並使用 LightGBM 進行比較。針對正負類別不平衡的問題，我調整類別權重，並透過分類門檻搜尋，評估不同設定對 Precision、Recall 與 F1 Score 的影響。

隨著特徵工程與模型設定的調整，報告中的驗證 F1 Score 從約 0.29 提升至約 0.57。最終 LightGBM 的 F1 達到 0.5696，高於 Logistic Regression 的 0.4592，反映出模型選擇與特徵設計對這項分類任務的重要性。

我也透過Training / Validation Logloss 與 F1 曲線觀察模型訓練過程。結果顯示，訓練集 F1 持續上升，但驗證集 F1 逐漸趨於平緩，使我更重視模型的泛化表現，而不只是訓練資料上的分數。

03

商品名稱價格預測

第二項專案以商品名稱預測商品價格為目標。由於商品名稱可能混用中文、英文、不同計量單位與特殊符號，若直接輸入模型，容易產生不一致的文字特徵，因此我先建立文字正規化流程。

前處理包含全半形統一、英文大小寫轉換、計量單位標準化與特殊符號清理。在特徵工程方面，我使用 HashingVectorizer 建立字元層級的 n-gram 特徵，並加入字串長度、數字數量及英文字符數量等數值特徵。

模型採用HashingVectorizer + Ridge Regression，並透過目標價格的 log 轉換處理長尾分布，減少極端價格對模型的影響。驗證階段使用五折交叉驗證（5-Fold Cross-Validation），以 SMAPE 評估價格預測誤差。

經過超參數比較，報告中選定的 Hashing + Ridge 模型，其平均 SMAPE 為 39.04。雖然部分 TF-IDF 替代模型在預測誤差方面具有優勢，但需要更長的訓練時間與較高運算資源，因此最終選擇在效能與計算成本之間較符合任務限制的模型。

這項實作讓我理解，模型選擇不只取決於預測指標，也必須考慮訓練時間、記憶體使用與推論限制。在實務應用中，建立可重複執行且符合資源限制的分析流程，同樣是重要的工程決策。

分類模型效能比較

以下為職缺與人才匹配專案的最終驗證結果。LightGBM 在 Precision、Recall 與 F1 Score 上均優於 Logistic Regression，並作為該次實驗的主要模型。

職缺與人才匹配模型最終驗證結果（原研究報告）
模型 Precision Recall F1 Score
LightGBM 0.5870 0.5531 0.5696
Logistic Regression 0.4090 0.5240 0.4592

這些結果顯示，在此資料集與特徵設定下，LightGBM 能取得較佳的 Precision 與 Recall 平衡。數值為原實驗報告中的驗證成績，並非獨立測試集或正式部署後的預測表現。
